# AIOps 연구 운영 플랫폼 UI 설계

## 목표

기존의 긴 단일 페이지를 연구실에서 실제로 사용할 수 있는 화면 전환형 운영
플랫폼으로 재구성한다. 사용자는 사이드바에서 목적을 선택하고, 중앙 작업 영역에서는
선택한 기능 하나에만 집중한다.

## 정보 구조

플랫폼은 다음 여섯 화면으로 구성한다.

1. `대시보드`: 클러스터 준비 상태, 4개 Agent, 장애 시나리오, 최근 실험을 요약한다.
2. `장애 실험`: Chaos Mesh 장애 4종과 비교 action 3종의 실험 매트릭스를 보여준다.
3. `Agent 판단`: 입력된 장애 상태에 대한 4-Agent mock 판단과 합의 결과를 생성한다.
4. `안전 검증`: Agent action이 실행되기 전에 통과하는 정책 경계를 보여준다.
5. `실험 결과`: 최신 recovery experiment와 정량 분석 산출물을 보여준다.
6. `연구 문서`: 실행, 시험, 정량 분석 가이드와 전체 아키텍처를 제공한다.

사이드바 항목은 동일 문서의 앵커로 이동하지 않는다. `#/dashboard`,
`#/experiments`, `#/decision`, `#/safety`, `#/evidence`, `#/documents`
해시 라우트에 따라 중앙 작업 영역 전체를 교체한다.

## 시각 원칙

- 첫 화면에 거대한 hero와 긴 연구 설명을 배치하지 않는다.
- 남색 사이드바와 밝은 작업 영역을 분리해 탐색과 내용을 시각적으로 구분한다.
- 페이지 섹션은 중첩 카드 없이 얇은 경계선과 충분한 여백으로 구성한다.
- 수치, 상태, action, 실험 결과는 표와 짧은 상태 행을 우선 사용한다.
- 모든 한글 문구는 UTF-8로 유지한다.
- 데스크톱에서는 고정 사이드바, 모바일에서는 가로 탐색 바로 전환한다.

## 기능 경계

- UI에서 실제 Kubernetes real action을 직접 실행하지 않는다.
- Agent 판단 화면은 기존 `/api/mock-alert` mock API만 호출한다.
- 실험 실행 명령은 연구자가 서버 CLI에서 수행하도록 표시한다.
- 기존 Python Coordinator, Validator, Go Guard, 실험 스크립트는 변경하지 않는다.

## 검증 기준

- 사이드바 클릭 시 페이지 스크롤이 아니라 독립 화면 전환이 일어난다.
- 각 화면에는 해당 목적과 관련된 정보만 표시된다.
- 1920x1080, 1366x768, 390x844에서 내용이 겹치거나 잘리지 않는다.
- 기존 Python 및 Go 테스트가 모두 통과한다.
